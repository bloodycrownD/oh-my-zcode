# backlog-sweep 真机 QA 附录

> 本迭代（`backlog-sweep`）落地面广（侧栏骨架重写、远端项目 Picker 真链、设备管理面板族、side-pane 全屏、服务商交互、胶囊富装填），自动化门禁只覆盖纯逻辑/源码形状与打包启动，**交互观感与真机链路必须手测**。本附录是验收清单，测完把结果记在最后一列。

## 0. 准备

- 用**生产打包产物**测（`pnpm --filter @zcode/desktop run build` → `out/`），不要用 dev server；启动即崩类问题只有打包产物能暴露。
- 远端链路需要一台可达的 SSH 目标机（或本机 WSL / 本机 Docker），并在目标机上放过一次 `zcode` server 产物。
- 桌面端 profile 建议分两轮：**现有 profile（升级）** 与 **全新 profile（首次安装）**——两条路径的迁移/引导分支不同。

## 1. T-QA1 远端项目 Picker 真链（对应 Step 4 / Step 9-10 与 v3.16 语义切换）

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 侧栏点「打开远程工作区」→ 连接向导 → 选目标（SSH/WSL/Docker）→ 连接 → 浏览目录 → 选一个目录 | 进入**项目创建/编辑**（不是直接切工作区）；编辑器里能看到 host 设备名与根目录 |
| 2 | 创建项目并保存 | 侧栏出现该远端项目节点；点开能看到项目树 |
| 3 | 同一目录再走一次「打开远程工作区」 | 已有项目时进入「已有项目」内嵌列表态，不再重复创建 |
| 4 | 取消/关闭向导 | 不残留半截 selection；再次打开是干净的首步（换代 key 生效） |
| 5 | 首次连 `source-server` 类目标 | 出现边界确认（omz 形态：普通确认框），**取消不落盘** |

> 已知语义切换（发布说明必须写）：此前「打开远程工作区」是直接进入工作区；现在改为进入远端项目创建。远端**建任务**的 host 路由属于下一轮（本轮 `start()` 带 `hostId` 非 `local` 时会给「暂不支持在远端主机创建任务」的 toast），这是有意收窄，不是坏点。

## 2. T-QA2 设备管理（对应 Step 7-10）

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 设置 → 远程设备 | 出现设备列表（本机 + 已连远端），设备卡显示状态/版本/线路 |
| 2 | 设备卡「编辑连接」 | 弹窗预填；清空主机名后保存 → 字段级错误高亮且**焦点落到 Host 输入框** |
| 3 | 设备卡「删除设备/删除线路」「设为默认线路」「开机重连」开关 | 立即生效、刷新后保持 |
| 4 | 设备卡「查看日志」/「迁移报告」 | 面板可打开、有内容或明确空态 |
| 5 | 侧栏远端项目节点的「设备设置」入口 | 跳到设置-远程设备并**定位到该设备** |
| 6 | 有可用更新时 | 顶部提示「有可用更新」；点「立即更新」→ 进度/结果 toast；点「详情」→ 更新活动面板 |

> 已知缺口（不是 bug，是本轮拍板/依赖缺口）：①设备卡主操作里 **connect/retry/install 在未接向导壳时是 disabled**（拍板 A：向导壳族不搬）；②「更新」依赖 release resolver，本仓未注入 → 点更新会得到 `release is unavailable` 的错误文案（面板顶部 alert + 详情按钮），**不会静默失败**；③`source-settings` scope 未接线（UI 当前不发起该 scope，不可达）。

## 3. T-QA3 胶囊（composer 选区/队列 chip）撤回与重发

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 选中一段对话内容 → 生成 chip → 再选同一段 | **不出现第二枚 chip**（内容键去重） |
| 2 | 撤回 chip → 重新选同一段 | 仍只有一枚 |
| 3 | 撤回 chip 后切到另一个会话/scope 再切回来 | 撤回状态还在、上下文不丢（随草稿持久化） |
| 4 | 选多段不同内容 | 多枚 chip 并存，顺序稳定 |

## 4. T-QA4 side-pane 全屏（对应 Step 19 / U10）

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 打开右侧 pane（文件/浏览器/终端任一）→ 点全屏 toggle（或 `Ctrl/Cmd+Shift+F`） | pane 进入全屏形态；对话区收成浮窗/solo 形态，不互相遮挡 |
| 2 | 全屏下切到「轨迹」tab | **轨迹面板正常渲染**（omz 特有：轨迹不受 `visible` 闸门约束，全屏下 tab 栏即使没有可见 tab 也保持可见） |
| 3 | 全屏下输入并发送 | 浮窗输入区可用、发送后消息滚动正常、底部 dock 高度自适应 |
| 4 | 关掉全屏 / 关掉 pane 再打开 | 全屏状态按 pane owner 记忆，不串到别的任务 |
| 5 | 多任务切换 | 每个任务各自的全屏状态互不影响 |
